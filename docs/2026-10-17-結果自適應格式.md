## 範圍與已確認決策

本文件在修改前建立中文計畫；本節與驗收結果依後續核准更新。來源專案由 ProjectHub 登錄確認為 `unitCalc repository`，scheme／target `unitCalc`，Bundle ID `tw.com.unlock.unitCalc`。開始基準 main `64419937c8e5318501f08ae76e7c2e75a18cb9f8`，本機版本 1.1.1 (3)。ProjectHub 唯讀，沒有修改 Glance、simStock3 或其他專案。

- 以結果列的實際可用寬度決定文字，不以方向設定固定小數位數。正常字型、字重、各版面字級與既有 Dynamic Type 上限保持原設計。
- 普通表示能容納就顯示；長小數逐步四捨五入，縮減後至少保留 3 位小數。整數部分加 3 位小數仍不合寬時改科學記號，正指數明示 `e+`。
- 極小非零數不能變成 `0.000`；改用有意義的科學尾數。科學尾數縮減後至少 3 位小數。精確簡單值如 `1.5`、`1`、`1e+20`、`1.5e-8` 不強補零。
- 首輪量測確認 iPhone 窄列無法同時滿足原 88pt、完整極大指數、尾數 3 小數；使用者後續明確核准「只有在極限不能完整顯示時，才允許縮小字體」。因此正式順序為：正常字級 → 小數縮減 → 科學記號 → **只有最短合規文字仍太寬時，整串縮至可完整容納的最大字級**。前一階段橫捲草案已取消，不再等待批准。
- 寬度增加後重新從正常字級計算；不橫捲、不獨立縮小指數、不截斷或省略結果。
- 只改顯示，不把格式化字串寫回計算值；不新增完整值檢視器或複製入口。

`calculator.swift` 完全未改，仍採有限精度 Double。新顯示初始以 13 位有效數字為基準，必要時依寬度減少；捨入跨位數仍保留必要的 3 位小數。這不是任意或無限精度計算。

原 `textCurrent`、`valueCurrent`、operands、memory、opLog、logText、outputText 均不回寫。既有可橫捲歷程與複製按鈕仍使用原 `logText`，因此不受窄結果列截短影響；歷程本身仍有原格式精度限制，不能稱為完整 Double 位元或無限小數匯出。現有介面沒有完整精度檢視器，本輪未新增。

App 保持原 POSIX 數字慣例（逗號分組、小數點），不另行改變輸入／歷程的 locale 語意。格式器另外測試德文、繁中、法文、印度與阿拉伯 locale。負號、分組符號、小數點、e 與指數正負號都納入整串量測。結果列本來不附單位；單位仍在選取器與歷程，不新增或漏算單位寬度。

UILabel 不啟用自動縮字。緊急縮字由程式在全部格式選項用盡後選擇，字串整體使用同一字級；窄→寬→窄皆重新計算。沒有非同步寬度狀態或方向快取，避免兩階段更新造成跳動；未量測逐幀動畫效能。

## 可重現驗收

| 情境 | 預期／已確認 |
| --- | --- |
| `1 ÷ 3 =`，直橫切換 | 普通小數以正常字級顯示；較寬結果列能顯示更多位數 |
| 接續 `× 3 =` | 為 `1`，不是用畫面上的縮短數字再計算 |
| `0`、負零、整數、`1.5` | 分別顯示 `0`、整數與 `1.5`，不補成 `1.500` |
| 輸入 `0.`、`1.00` | 編輯字串保留；按等於後 `1.00` 成為 `1` |
| `2/3`、負值、平方根 | 依寬度正確捨入；例：3 小數的 `0.667`、`-0.667` |
| `999.999996` | 捨入後測量 `1,000.000`；不足時改 `1.000e+3` |
| `9.99996e99` | 科學進位邊界可成為 `1.000e+100`，重新量測完整指數 |
| `1.23456789e-8`、最小非零 Double | 不顯示零；可為 `1.235e-8`、`5e-324` |
| 最大 Double、負的大數 | 完整 `e+308`／`e+100`；必要時才整串縮字 |
| 窄寬尺寸 | 實際 UILabel 在 160–1300pt 寬、56–254.8pt 字級的矩陣測試均合寬；正常可容納時不縮字 |
| 記憶、歷程與換算 | 原值／歷史不變，memory recall 與後續公克→公斤計算通過 |
